## 席順作成の仕組み

<a href={env.urls.forseti}>管理画面</a>の**対局管理**で作成します。全体の流れは<a href='/jp/forHosts#tournament'>大会運営ガイド</a>をご覧ください。一卓四人、三麻三人が必要です。対象名簿を確認してください。画像は英語画面とテストデータです。

### ランダム席順

順位でグループ分けせずにシャッフルします。過去の結果が不要で、初回に使える自動方式です。事前指定イベントなら初回からスクリプトを使えます。

複数のシャッフル案を試し、過去の席順との再対戦を比較して、見つかった中で最も良い案を採用します。その後、設定に従い起家時の風を割り当てます。履歴がある場合は完全に無制約な抽選ではありません。特に後半は再対戦もあり、新しい相手や順位の近い相手を保証しません。

### スイス式席順

現在順位と対戦履歴から、近い順位のプレイヤーをまとめつつ再対戦を減らします。両方を同時に満たせないことがあり、再対戦は必ずしも誤りではありません。過去の対局後に使用可能です。次の作成前に結果を承認してください。

#### 卓を作る手順

**対戦回数**は二人が同卓した回数です。二度同卓すれば二回であり、過去に同卓したかどうかだけではありません。

1. 順位と履歴から、まだ割り当てていない最上位のプレイヤーを次の卓に置きます。
2. その卓の誰とも同卓していない候補のうち、最上位を探します。
3. 四人（三麻は三人）まで繰り返します。候補は最初の人だけでなく、既に選んだ全員と照合します。
4. 決まった人を除き、残る最上位から次の卓を始めます。
5. 選択のために残りの卓が現在の対戦制約で完成しなくなる場合、戻って別の候補を試します。最初に有望だった卓が最終結果とは限りません。
6. 再対戦を避けられなければ許可します。選ばれた人との過去の対戦が少ない候補を優先し、その中で順位の高い人を選びます。
7. 全員を配置してから、指定モードで起家時の風を決めます。

組合せ探索なので人数が増えると全案の試行は現実的でありません。計算量が増すと対戦制約を緩めて探索量を制限します。全体最適や再対戦回数の絶対最小は保証しません。

後ろの卓ほど候補が少なく、重複回避が難しくなります。卓数より実際の履歴が重要です。卓数が二の累乗でも重複ゼロは保証せず、他の卓数も対応します。

### 間隔指定席順

現在順位を指定間隔でまとめます。対戦履歴による重複回避は行わず、過去の対局後に使用できます。

- 間隔 **1**：1–2–3–4、次に5–6–7–8。
- 間隔 **2**：1–3–5–7、次に2–4–6–8。
- 大きな間隔ほど順位差が広がり、残った人は後の卓に入ります。
- 三麻は三人で、間隔1なら1–2–3、間隔2なら1–3–5です。

#### グループと余りの卓

間隔は正の整数です。四人卓で間隔3なら、順位を十二人ずつのブロックに分け、三卓を作ります。

- 卓1：**1–4–7–10**。
- 卓2：**2–5–8–11**。
- 卓3：**3–6–9–12**。

次は13–24位を同様に扱います。卓はその卓の最上位者順です。ブロック内を分散する方式であり、全選手を全卓へ均等分散するものではありません。

卓数が間隔で割り切れない場合、完全なグループを作れない下位の選手は**間隔1**で組みます。16人・間隔3なら最初の十二人が上の三卓、**13–14–15–16**が残りの卓です。間隔が全卓数を超える場合は全卓がこの扱いです。

三麻の完全グループは間隔の三倍の人数で、間隔3なら九人です。余りも隣接順位で組みます。通常グループも余りも過去の相手を避けないため、余りの卓に再対戦が集中する場合があります。

### 事前指定席順

**席順を事前に指定**を有効にし、**プレイヤー管理**で**ローカル ID**を保存し、**事前指定席順**に計画を入力します。一行一卓、ID はハイフン区切り、空行が次のセッションです。四人分、三麻は三人分を指定します。

<GuideScreenshot name="predefined-ids" alt="イベント専用のローカル ID 一覧。スクリプトに使うのはアカウントの System ID ではありません。" caption="イベント専用のローカル ID 一覧。スクリプトに使うのはアカウントの System ID ではありません。" />

**次のセッション番号**を対象ブロック（1から）に設定し、更新してエラーを直します。**次の席順**でそのブロックを生成します。番号はタイマー開始で進み、承認後に次へ進めます。残りがなければ先に追加・検証します。<a href='/jp/forHosts#predefined'>手順と例</a>もご覧ください。

#### スクリプトと自動方式の切替

最初の生成前に ID の対応と全体計画を保存する必要があります。自動方式は、その時点の登録選手、順位、対戦履歴から次を計算します。

**席順を事前に指定**を無効にすると、既存の結果と履歴を使う自動方式が利用できます。後で戻す場合はスクリプトと**次のセッション番号**を確認し、実際に行うブロックを選びます。モード変更は対応するスクリプトの作成や過去の対局の削除を行いません。進行中に切り替えず、事前に準備してください。

### 卓の組合せと起家時の風

席順方式は同卓者を決め、**風の割当モード**が卓内の初期座席を決めます。

- **ランダム：** 各卓で無作為に割り当てます。
- **均等化：** 各人がこれまで少なく座った風を優先します。
- **スクリプト順：** 事前指定では各行の東–南–西–北（三麻は東–南–西）の順にします。

**席順準備完了**で卓と風を確認し、誤りは開始前に**席順をリセット**します。全員着席後、**タイマー開始**で全卓を同時に始めます。
